# ADR-004: explicit kiosk workflow
Use XState 5 with invoked asynchronous actors and React subscribed snapshots, without another UI dependency. Scenario list and menu data come from the same validated contract; no cafe-specific rendering. Options enforce one per group, required options, packing, quantity and cart limits. Keep a frozen submission payload including client active time until result or confirmed cancellation. No back/edit transitions during ambiguous submission; a retry uses identical data. Cancellation and grading share the PostgreSQL row lock, so neither overwrites the other. A lost initial session creation response may leave an active orphan; expiry/recovery across browser reload is future work. Visible interactive time is approximate client-reported time, not measured attention. Help and high contrast are optional user-controlled presentation. Keyboard, focus and axe are tested; no claim of full WCAG certification. No real payments or customer data.
