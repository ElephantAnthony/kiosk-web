# ADR-005: durable outbox and atomic event acknowledgment

Status: source verified with 42 Java, 22 Vitest and 9 browser tests; mandatory generated OpenAPI re-verification pending. Evidence: ../evidence/runs/SEN-05-event-45776976931.md.

Each accepted user action or state transition is mapped to an allowlisted event in telemetry.ts. track() creates a UUID, client timestamp and session/scenario metadata. One IndexedDB read-write transaction increments a per-session sequence and inserts the event. The sequence store is not reset when ACKed rows disappear. The persisted event is immutable during retries. Both Java and Ajv consume event.schema.json; the server also checks menu/category/group/option references against the stored scenario version. No names, free text, card details, or demographic fields. Client timestamps and events are behavioral reports, not proof of actual payment or successful completion. Use server mission_result for authoritative completion.

Flush takes up to 20 rows for one session and orders them by sequence. A 5-second interval, 20-row threshold, and online event trigger delivery. Single in-process flush and Web Locks (where supported) reduce concurrent transmissions; database uniqueness remains the correctness boundary. If no Web Locks API is available, tabs may send duplicates. ACK must contain exactly the sent IDs; incomplete, foreign or repeated ACK IDs do not delete any rows. The batch API is atomic rather than partial-success. On network errors, retry with bounded exponential backoff and jitter; a 429 Retry-After delta or HTTP date takes precedence if longer. 400/403/404/409 retain the rejected session's records and block that session in the current page instance, leaving other sessions eligible. Reload retries retained records. No silent discard. pagehide attempts a bounded keepalive flush, not a guaranteed unload delivery.

Server uses cookie-bound CSRF and the owner predicate on a session row lock, then validates the entire batch. INSERT ON CONFLICT DO NOTHING plus JSONB equality accepts identical event identity, rejects changed identity or sequence collision. The entire transaction rolls back on conflict. Event UUID is unique globally and (session_id, sequence) is unique. Late events for completed/cancelled sessions are allowed; ingestion never mutates mission results or terminal status.

Alternatives: localStorage has no multi-store transaction; in-memory buffering loses records on reload; broker/Redis adds unneeded infrastructure. The current solution does not guarantee delivery after origin storage eviction, quota error, cookie expiry, browser termination before transaction commit, or cross-device changes. An expired cookie cannot authorize old pending events. No automatic retention deletion or production use is claimed. User-visible status indicates storage failure or blocked/retrying delivery. Real PostgreSQL and Chromium tests are the release gate; unit tests alone do not establish durability.
