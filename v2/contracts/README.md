# Shared contracts

The JSON Schema Draft 2020-12 file scenario.schema.json is the structural source of truth. The fictional cafe fixture is immutable by (scenarioId, version). Spring validates with networknt 1.5.9; frontend validates with Ajv 8.17.1 using the exact same JSON file. The API client validates scenario responses before use. Server semantic validation additionally checks unique IDs, category references, option group cardinality and mission references. No actual brand assets or payment data. The event schema is intentionally deferred to the event milestone; no event ingest is implemented here.

OpenAPI 3.1 generated by Springdoc is committed as openapi.json. CI regenerates it and rejects differences; it is not manually authored. The scenario schema is separately shared between Java and TypeScript. Use a new scenario version when changing a persisted definition.

The second fictional scenario doran-burger.v1.json was added in a fixture-only commit. The generic server and renderer load both through the same schema; no schema modification was needed. Actual browser verification is separate from structural validation.
